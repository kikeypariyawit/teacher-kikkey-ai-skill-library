# Production handoff and change control

Read this for a full episode pack, long-running series, or GitHub-backed production. Keep simple requests small.

## Full production package
Return the requested layers in usable order:
1. Episode intent, inherited canon, audience promise and episode question.
2. Screenplay with scene headings, present-tense action, exact speaker/dialogue, reactions and estimated timing.
3. Story decisions, planted evidence, payoff and consequential cliffhanger.
4. Character/world updates, location staging and visual/acting direction.
5. Stable shot table: edit duration, beat, geography, camera, entry/exit and dialogue.
6. Asset bindings and per-shot generation mode; start/end yes/no with reasons.
7. Separate finished frame/video prompt blocks only where required.
8. Edit/sound cue sheet and fallbacks for difficult coverage.
9. Draft continuity delta, acceptance status and next-scene entry state.
10. Evidence-based preproduction QA plus unperformed media checks.

When images/video are requested and tools and authorization exist, execute the media work; a prompt pack alone is not the requested film. A skill-upgrade request itself does not request a rendered episode. Do not ask for generated footage to complete preproduction QA.

## Source ownership and GitHub
Use the user's established project repository when available. Inspect AGENTS.md and existing paths before editing. Preserve prior approvals and existing unrelated skills. Use the existing character/project/continuity/status files as source owners; add lookbook, cue sheet or manifest only where useful instead of duplicating canon.

Record proposed changes as draft until accepted; existing user approval or standing authorization counts and should not be requested again. Track change ID, affected scene/shot/asset IDs, reason, old/new state, status and downstream changes. A dialogue edit can require retiming captions and reaction shots; a costume change affects visual assets; a clue edit affects knowledge and future payoffs. Do not rewrite unrelated episodes.

For requested GitHub updates, read the latest source, write a focused versioned change, run available relevant validation, preserve unrelated files, and verify the saved paths/content. Use a branch/PR if required by repository rules; otherwise respect the authorized workflow. Do not force-push, publish source assets, change repository visibility or install third-party executable code as a side effect. Avoid secrets and large raw renders in a reusable skill repository; keep project media in the project's existing artifact store and track permitted references.

A repository copy is a source bundle, not proof that a separate application has loaded/installed its skills. State separately which available skill was updated and which GitHub files were saved. Do not claim universal automatic activation or synchronized changes without verified integration.

## Completion evidence
Use ผ่าน / ต้องแก้ / ยังไม่ตรวจ and concrete evidence per domain. Review story causality, emotional progression, dialogue, timing, spatial logic, identity bindings, frame necessity, art direction, sound plan and output completeness. A critical story, identity, speaker or endpoint defect blocks a ready verdict regardless of an average score.

If scoring is requested, label scores as editorial judgments with examples, not measurements or predicted audience retention. A script can pass preproduction while motion, voice, lip-sync and final image quality remain untested. Review actual motion for animation/physics, actual audio for voice/sync, and the assembled file for final technical delivery. State what exists and what remains; do not invent a 100/100 badge.
