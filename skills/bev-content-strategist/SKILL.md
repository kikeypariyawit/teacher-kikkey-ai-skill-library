# bev-content-strategist

## Purpose

Plan fresh, useful, non-repetitive content for Bangyai English Village that builds trust, engagement, and enrollment intent among parents.

## Use when

Use for BEV content calendars, daily post ideas, campaign pillars, educational posts, seasonal posts, or requests for a new topic that must avoid repetition.

## Required inputs

- Goal/campaign context
- Audience segment or parent concern
- Publishing surface/timing if known
- Recent topics or exclusions if available

## Workflow

1. Define the single parent insight or problem the content should address.
2. Check for topic duplication and deliberately choose a fresh angle, mechanism, story, misconception, observation, or activity lens.
3. Choose one objective: educate, reassure, inspire, demonstrate, invite, or convert.
4. Build a hook that can be understood within 2 seconds on mobile.
5. Develop one core takeaway; do not stack unrelated benefits.
6. Connect the insight naturally to BEV after delivering genuine value.
7. Provide a premium visual/video concept.
8. End with a low-friction CTA appropriate to the funnel stage.

## Output contract

- Content idea/title
- Parent insight
- Hook
- Core message
- Visual/video concept
- CTA

## Final QA

- Not substantially repetitive with supplied/recent themes
- Useful even if brand name were removed
- Age-appropriate and parent-trustworthy
- No inflated education/health claims
- Mobile-first

## Operating rules

- Preserve explicit user constraints over defaults in this skill.
- Do not invent missing facts, dates, prices, references, research support, or asset state.
- Prefer concrete decisions and finished outputs over generic advice.
- Keep the result easy to hand off to the next skill.
- If an external action needs an unavailable tool or permission, complete every possible upstream step and state the blocked action clearly.

## Execution handoff

Use [create-bev-content](../create-bev-content/SKILL.md) for finished BEV content and its freshness-and-social reference for semantic duplicate checks. Compare parent need, underlying takeaway, concrete example/action and visual family with the actual available history. Check a user-named pipeline before claiming it was consulted; do not invent publication records or cross-session memory.

Use [social](../social/SKILL.md) selectively for carousel narratives, hook variants and short-video structure. Keep one owner for topic and factual claims. Respect no-selling briefs and avoid guilt, unsupported outcomes, fabricated testimonials or false scarcity. A caption or image request needs the requested finished deliverable, not only the strategy fields above.
