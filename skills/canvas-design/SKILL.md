Modified 2026-09-13 from Anthropic's canvas-design. Copyright 2026 Anthropic, PBC. Licensed under Apache-2.0; see LICENSE.txt. This personal edition replaces the original art-manifesto workflow with practical mobile design. See [references/source-adaptation.md](references/source-adaptation.md).

## Read the brief and the actual references

Identify purpose, viewer, exact copy, dimensions, deliverable count and source assets. Classify each reference as original logo, original photo, accepted artwork, style reference or content source. An old poster may establish mood but not current prices or actual child identity.

Use explicit user choices over defaults. Infer routine creative choices. A caption-only request does not need this workflow; a narrow edit does not need three redesigns.

For BEV, let design-kids-education-graphics own production and authenticity. Supply a concise visual direction, then execute the requested deliverable through the available appropriate tools. Do not present an art manifesto instead of the finished graphic.

## Make a visual idea

Write one internal sentence: what should the viewer notice and understand first?
Compare three genuinely different compositions for a broad design task. Change scale, focal position, reading path or story, not only color.

Examples of composition families:
- One documentary moment with an adjacent clear text field.
- Oversized typography with one small meaningful object.
- An asymmetric photo sequence showing an action unfolding.
- A restrained editorial illustration built around a gesture or object.
- A structured event poster where name, date and offer form one group.

Choose the direction that serves the message and available assets. Do not impose one style on all posts. Bright event artwork can be energetic; parent advice can be quiet. Premium does not mean beige or tiny text.

## Direct what can actually be seen

Specify:
1. Dominant subject, scale, crop and action.
2. Headline placement and reading order.
3. Supporting blocks and clear space.
4. Palette roles and contrast, preserving natural skin.
5. Type character and Thai mark clearance.
6. One motif, if it helps communicate the concept.
7. What must remain unchanged.

For real photography, select the strongest existing expression or interaction instead of instructing AI to beautify a child's face. Do not alter identity, expression, anatomy, clothing or safety equipment unless the current user instruction explicitly authorizes a compatible edit. Never claim exact pixel preservation from generation.

For BEV, avoid default stacks of leaves, wooden signs, speech bubbles, sticker badges and repeated slogans. Use the official supplied logo, not a recreation. Keep text off faces and working hands.

Use strong friendly Thai-capable type for parent-facing information. Do not inherit the upstream preference for thin fonts or tiny museum labels. Check actual font/glyph availability when typesetting; no bundled Latin font is presumed to support Thai.

## Produce and refine

Follow the user's selected medium and active tool contract. Use the image-generation tool for requested raster creation and editing. Use an allowed native layout workflow when exact editable text or photo layers are needed. Do not use code drawings as a substitute for requested generated illustration; do not silently bypass an image-editing restriction.

Supply exact quoted text, input roles, composition, palette/light and invariants to image generation. Keep prompts concrete and compact. Repeating prestige adjectives does not replace decisions.

Inspect the actual result at full size and phone size when available. Improve crop, alignment, text breaks, spacing, focal contrast or irrelevant decoration based on visible defects. Avoid adding more objects merely to make the work feel richer.

For multiple images, keep the brand system coherent while giving each its own message and composition. Respect per-image ratios and separate-file requests. Only make a joined panorama when requested.

Stop when the requested image is clear, accurate and coherent. Report any unverified limitation precisely; do not invent visual QA, image dimensions, editable layers or platform previews.
