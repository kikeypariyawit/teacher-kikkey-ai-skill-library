# Freshness and social execution

Use this for new-topic requests, repeated complaints about duplication, calendars, and promotional variants. Do not burden caption-only or narrow-edit requests with the full process.

## Recover the available history

Read the supplied history, the accessible project content log, or the user's named Content Pipeline. If a source is unavailable, use the history actually visible and do not claim a live check. A named source must be checked through an authorized connector before claiming it was used. Do not silently substitute memory for a requested pipeline check.

Compare concepts by these fields, not titles alone:
- Parent need and age/application context.
- Underlying message or benefit.
- Concrete child moment, object or situation.
- Action/example offered to the parent.
- Hook structure, format and visual family.

For a request for new content, reject candidates with the same underlying takeaway and parent action as a recent example. Changing a child, location, headline or background is insufficient. If the user explicitly requests a previously used topic, preserve the topic and choose a new application rather than vetoing it.

## Select the useful angle

Consider three different parent needs or applications internally. Select the strongest by usefulness, source availability and distinctness. Avoid automatically returning to confidence, screen reduction, outdoor benefits or generic family warmth when those dominate the available history.

Use a specific observation, worked English exchange, practical decision, materials-based activity, behind-the-scenes process or clearly framed imagined situation. Do not invent an observed incident to make the content emotional. An object-led graphic may suit a general tip; it must not claim to show an actual BEV event.

Freshness example: after a post about letting children try again to build confidence, a post about letting them climb again to build courage is still close. A new application such as giving a partner precise building instructions has a different action and useful language goal. This is an example of differentiation, not a permanent topic blacklist.

## Use a social structure without losing the substance

Use installed social when a carousel narrative, hook comparison or short-video structure needs work. Keep this skill as the topic and brand owner. Do not load the full social skill for an already finished caption correction.

Match one objective to one structure:
- Practical value: recognizable situation → exact example/action → takeaway.
- Emotional connection: everyday detail → emotional turn → kind close, without guilt or forced selling.
- Activity evidence: visible action → what can be observed → modest invitation.
- Enrolment: experience → verified offer/conditions → single enquiry action.

Write Thai as a person addressing parents, not a translated marketing formula. Avoid generic opening questions, invented statistics, diagnosis, guarantees and false urgency. Do not promise virality.

For promotional variants, vary one principal angle or headline while preserving the same verified offer. Label variants as hypotheses, not winners. Use supplied performance data to choose between them; engagement alone is not proof of enrolment impact.

## Keep a truthful project log

Use an existing project log when available. Otherwise prepare a compact row only when ongoing production or a calendar makes it useful:

| ID | Status | Topic | Parent need | Core takeaway | Example/action | Hook | Visual family | Source | Nearest prior item | Meaningful difference |
|---|---|---|---|---|---|---|---|---|---|---|

Use draft, approved or published only when supported. Do not mark generated material as posted. Do not embed private photos, child names, volatile offers or a growing content history inside this reusable skill. Store working records in the authorized project location, not the skill.

A request to draft content does not automatically authorize external Notion or GitHub writes. Persist the row when the user or established project workflow authorizes that action. If not persisted, do not say future sessions will automatically know the new row.

For multi-post requests, compare the new posts with one another as well as history. Separate useful novelty from a merely different graphic. Deliver the requested number without duplicate filler.
