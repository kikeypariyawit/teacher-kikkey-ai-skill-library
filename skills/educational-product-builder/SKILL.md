# educational-product-builder

## Purpose

Design practical, sellable English-learning products for children, parents, and teachers with clear age fit, objectives, activities, and answer support.

## Use when

Use for E-books, worksheets, printable packs, lesson materials, games, activity books, and classroom resources.

## Required inputs

- Age range
- Topic/language target
- Product format
- Page/lesson count
- Buyer type

## Workflow

1. Define the learning objective and observable success criteria.
2. Set vocabulary, sentence-pattern, reading, and cognitive load for the age.
3. Progress from recognition to guided practice to independent use.
4. Vary activity mechanics to avoid worksheet fatigue.
5. Write short, testable child-facing instructions.
6. Include answer keys, teacher/parent notes, differentiation, or extension only when useful.
7. Design for both learning value and perceived commercial completeness.

## Output contract

- Product concept
- Age/level
- Learning objectives
- Scope/sequence
- Page/activity plan
- Sample content
- Answer-key plan
- Packaging ideas

## Final QA

- Age appropriate
- Instructions unambiguous
- Objective measurable
- No accidental answer cues
- Value beyond generic free worksheets

## Operating rules

- Preserve explicit user constraints over defaults in this skill.
- Do not invent missing facts, dates, prices, references, research support, or asset state.
- Prefer concrete decisions and finished outputs over generic advice.
- Keep the result easy to hand off to the next skill.
- If an external action needs an unavailable tool or permission, complete every possible upstream step and state the blocked action clearly.
