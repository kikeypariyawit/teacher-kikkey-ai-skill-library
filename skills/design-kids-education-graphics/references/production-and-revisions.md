# Production and revisions

## Keep source roles explicit

Record only the useful task facts: asset role and accessible path, exact text blocks, dimensions, changes requested, and elements to preserve. Do not embed transient attachment paths, private child photos, or current prices into the reusable skill.

Use supplied style references for high-level composition, light, palette, and type hierarchy. Do not copy another creator's distinctive characters, complete layout, or wording. Keep a source's factual content separate from its style.

## Match the workflow to the requirement

| Requirement | Preferred approach when allowed | Limitation to check |
|---|---|---|
| New illustration or textured artwork | Available image-generation tool | Inspect anatomy, visual story, and rendered copy. |
| Short integrated headline | Exact quoted strings in generation, or editable typesetting | Read every glyph; do not treat model compliance as guaranteed. |
| Dense Thai or precise offer details | Separate editable typesetting over the visual | Check actual font availability and line breaks. |
| Exact authentic photo preservation | Original photo as an unchanged source layer, proportional placement | Cropping may hide important action; generative editing cannot prove unchanged pixels. |
| Official logo | Original asset inserted at preserved proportions | A prompted recreation is not an unchanged logo. |
| Data, ordered facts, or exact diagram | Deterministic chart/layout tools | Decorative generation must not decide quantities or relationships. |

The active tool contract takes precedence over these preferences. Do not use an otherwise prohibited tool or hidden compositing route to satisfy this table. If the required combination is unavailable, identify the specific conflict and deliver the feasible draft or ask only for the missing input that resolves it. Do not leave a full image request as only a prompt when generation is available and suitable.

For permitted image-generation work, structure a concise prompt around purpose, input roles, exact copy, dominant subject and action, composition, medium, lighting/palette, dimensions, and invariants. For a generative edit of real people, explicitly forbid changes to identity and anatomy, but do not describe the output as pixel-identical.

## Narrow revisions

Define the edit scope from the latest request. Reuse the accepted source or editable document when available; do not restart from an old version. Change a price, date, logo, or phrase only where requested, checking dependent totals or repeated instances where relevant. Preserve unrelated offers and layout choices.

For a ratio change, recompose: move text, adjust whitespace, and recrop proportionally around the same subject. Never stretch the design. A ratio-only edit preserves copy and imagery unless the crop makes a new choice necessary. Explain unresolved orientation contradictions; otherwise infer from the latest clear user direction.

If the user says “continue,” first inspect the latest accessible artifact and completed work. Do not regenerate finished pages or replace approved characters. If that artifact is unavailable, say so rather than inventing continuity.

## Multiple images and carousels

Treat “four images” as four separate deliverables unless the user requests a combined sheet. A contact sheet is only a preview. Specify the role of each image before production, use a shared type/palette system, and avoid unintended repeated photos or duplicated copy. Keep per-image messages understandable independently while the sequence develops the topic.

Use a panoramic connection only when requested. For a connected sequence, align adjoining edges and distribute the subject so faces and words do not cross seams. Do not claim images connect without inspecting them side by side.

Follow requested per-image ratios, including a portrait cover and square supporting pages. Do not assume a platform will display an album in a particular tile arrangement. Keep important content within each image's own safe area and verify a live preview only if the platform layout itself is part of the task.

## Handoff and recovery

Use ordered, descriptive versioned names for exported files, and retain editable sources when actually created and useful. Follow current saving rules; do not invent a permanent location or claim a flattened raster is editable. When a generated image is already displayed and automatically saved, do not create duplicate downloads merely for the handoff.

After a tool error, distinguish unavailable input from failed generation or failed saving. Recover using the current supported mechanism without guessing paths or claiming access that was not verified. Tell the user only what still prevents completion.
